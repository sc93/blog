오늘은 NestJS 프로젝트를 생성하고 실행해 봤습니다. 기본으로 만들어지는 파일들이 어떤 역할을 하는지, 애플리케이션이 어떻게 시작되고 요청에 응답하는지 공부했습니다.

NestJS가 어떤 도구인지부터 프로젝트의 기본 구조와 실행 과정까지 복습하며 정리해 보겠습니다.

## 1. NestJS란?

NestJS는 Node.js 환경에서 서버 애플리케이션을 개발하기 위한 프레임워크입니다. TypeScript를 기본적으로 지원하며, JavaScript로도 사용할 수 있습니다.

서버 개발에서는 요청 처리, 데이터 조회·저장, 입력 검증 등 여러 작업이 필요합니다. NestJS는 이런 코드를 역할에 따라 나누고 연결할 수 있는 구조를 제공합니다.

| 구성 요소  | 기본 역할                                      |
| ---------- | ---------------------------------------------- |
| Module     | 관련 기능을 묶고 구성 요소를 등록합니다.       |
| Controller | 요청을 받아 처리하고 응답을 반환합니다.        |
| Provider   | 필요한 곳에 주입해서 사용할 기능을 제공합니다. |

처음에는 세부 동작을 모두 외우기보다, **역할에 따라 코드를 나누고 NestJS가 이를 연결한다**는 점부터 이해하면 좋습니다.

## 2. Node.js와 NestJS는 어떻게 다를까?

Node.js와 NestJS는 서로 다른 역할을 합니다.

| 구분 | Node.js                           | NestJS                              |
| ---- | --------------------------------- | ----------------------------------- |
| 종류 | JavaScript 런타임                 | 서버 애플리케이션 프레임워크        |
| 역할 | 브라우저 밖에서 JavaScript를 실행 | 서버 개발에 필요한 구조와 기능 제공 |
| 관계 | 애플리케이션이 실행되는 환경      | Node.js 위에서 사용하는 도구        |

Node.js가 코드를 실행하는 환경이라면, NestJS는 그 환경에서 서버 애플리케이션을 구성하도록 도와주는 프레임워크입니다.

## 3. Nest CLI란?

CLI는 Command Line Interface의 약자로, 터미널에서 명령어로 도구를 사용하는 방식입니다.

Nest CLI는 프로젝트 생성이나 구성 요소의 기본 코드 생성을 도와주는 도구입니다.

```bash
nest new nest-study --package-manager pnpm
```

이 명령은 `nest-study`라는 프로젝트를 생성하고 패키지 매니저로 pnpm을 사용하도록 지정합니다. 실행하려면 Nest CLI가 설치되어 있어야 합니다.

CLI가 초기 구성을 만들어 주기 때문에 개발자는 필요한 기능을 작성하는 데 집중할 수 있습니다.

## 4. 기본 파일은 어떤 역할을 할까?

프로젝트를 생성하면 애플리케이션을 시작하고 요청을 처리하기 위한 기본 파일들이 만들어집니다.

| 파일                     | 역할                                            |
| ------------------------ | ----------------------------------------------- |
| `main.ts`                | 애플리케이션을 초기화하고 서버를 실행합니다.    |
| `app.module.ts`          | 애플리케이션의 루트 모듈을 정의합니다.          |
| `app.controller.ts`      | 기본 HTTP 요청을 처리합니다.                    |
| `app.service.ts`         | Controller가 사용할 처리 로직을 제공합니다.     |
| `app.controller.spec.ts` | Controller의 동작을 확인하는 테스트 코드입니다. |

`AppModule`은 애플리케이션 구성의 출발점이 되는 루트 모듈입니다. 기능이 늘어나면 게시글이나 사용자처럼 기능별 모듈을 만들어 연결할 수 있습니다.

## 5. 애플리케이션은 어떻게 시작될까?

`main.ts`의 핵심 실행 코드는 다음과 같습니다.

```ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(3000);
}

bootstrap();
```

`bootstrap()`은 애플리케이션을 초기화하는 함수입니다.

`NestFactory.create(AppModule)`은 루트 모듈을 바탕으로 구성 요소와 의존 관계를 구성하고 애플리케이션 인스턴스를 생성합니다.

이후 `app.listen(3000)`이 서버를 시작해 3000번 포트에서 요청을 받을 수 있도록 합니다.

즉, **애플리케이션을 구성하는 과정과 요청을 받을 서버를 실행하는 과정**으로 나누어 볼 수 있습니다.

## 6. 요청은 어떻게 처리될까?

서버가 실행된 뒤 요청이 들어오면, NestJS는 요청의 HTTP 메서드와 경로에 맞는 Controller 메서드를 찾습니다.

```ts
@Controller('hello')
export class HelloController {
  @Get()
  sayHello() {
    return 'Hello NestJS!';
  }
}
```

이 Controller가 모듈에 등록되어 있고 별도의 전역 경로 설정이 없다면, `GET /hello` 요청을 처리합니다.

| 코드                     | 의미                                   |
| ------------------------ | -------------------------------------- |
| `@Controller('hello')`   | Controller의 공통 경로를 지정합니다.   |
| `@Get()`                 | GET 요청을 처리할 메서드를 지정합니다. |
| `return 'Hello NestJS!'` | 응답으로 보낼 값을 반환합니다.         |

메서드 이름이 `sayHello`이기 때문에 요청과 연결되는 것은 아닙니다. **데코레이터에 선언한 HTTP 메서드와 경로가 요청과 일치하기 때문에 실행됩니다.**

처리할 로직이 많아지면 Controller에서 Service를 호출하도록 나눌 수 있습니다.

## 7. 개발 모드로 실행하기

생성한 프로젝트에서는 다음 명령으로 개발 서버를 실행할 수 있습니다.

```bash
pnpm run start:dev
```

개발 모드는 파일 변경을 감지해 다시 빌드하고 서버를 재시작하므로, 코드를 수정한 뒤 결과를 확인하기 편리합니다.

프로젝트 생성은 기본 구성을 준비하는 작업이고, 개발 서버 실행은 그 애플리케이션을 실제로 동작시키는 작업입니다.

## 8. 기억할 점

NestJS가 구조를 제공하더라도 파일을 만드는 것만으로 모든 기능이 자동 연결되는 것은 아닙니다. Controller와 Provider를 모듈에 등록하는 등의 구성이 필요합니다.

또한 CLI 버전과 생성 옵션에 따라 파일 구성이나 설정은 달라질 수 있습니다. 파일 이름을 외우는 것보다 **실행 진입점, 루트 모듈, 요청 처리, 실제 로직의 역할을 구분하는 것**이 중요합니다.
