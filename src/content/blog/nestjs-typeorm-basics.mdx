오늘은 NestJS에서 데이터베이스를 연결하는 부분을 공부했습니다. PostgreSQL을 사용하고, TypeORM으로 연결하는 과정에서 ORM, 엔티티, 리포지토리라는 개념을 접했습니다.

각각 어떤 역할을 하는지, 서로 어떻게 연결되는지 복습하며 정리해 보겠습니다.

## 1. PostgreSQL이란?

PostgreSQL은 데이터를 저장하고 관리하는 오픈 소스 데이터베이스 관리 시스템입니다. 줄여서 Postgres라고도 부릅니다.

관계형 데이터베이스에서는 데이터를 테이블 형태로 관리합니다. 예를 들어 게시글 테이블에는 다음과 같은 데이터를 저장할 수 있습니다.

| id  | title      | content        |
| --- | ---------- | -------------- |
| 1   | 첫 번째 글 | 오늘 배운 내용 |
| 2   | 두 번째 글 | 복습한 내용    |

테이블의 **행**은 게시글 한 건을, **컬럼**은 제목이나 내용처럼 데이터의 항목을 나타냅니다. 이렇게 저장된 데이터는 SQL이라는 언어로 조회하거나 추가·수정·삭제할 수 있습니다.

```sql
SELECT id, title FROM posts;
```

위 SQL은 `posts` 테이블에서 모든 행의 `id`와 `title`을 조회한다는 뜻입니다.

PostgreSQL은 관계형 구조에 객체 관련 기능을 확장한 객체 관계형 DBMS입니다. 처음에는 **테이블에 데이터를 저장하고 SQL로 관리하는 도구**로 이해하면 출발하기 좋습니다.

## 2. ORM이란?

애플리케이션에서는 데이터를 객체로 다루고, 관계형 데이터베이스에서는 테이블의 행과 컬럼으로 다룹니다.

예를 들어 애플리케이션에서는 게시글 객체의 `title` 속성을 사용하지만, 데이터베이스에서는 게시글 테이블의 `title` 컬럼을 사용합니다. 서로 표현 방식이 다르기 때문에 둘 사이를 연결하는 작업이 필요합니다.

**ORM은 Object-Relational Mapping의 약자로, 객체와 관계형 데이터를 연결하는 기법입니다.** 일반적으로 이 연결을 처리해 주는 라이브러리도 ORM이라고 부릅니다.

ORM을 사용하면 객체를 다루는 코드로 데이터 조회나 저장을 요청할 수 있습니다. ORM은 그 요청에 필요한 SQL을 구성하고 실행하며, 조회 결과를 객체로 다룰 수 있게 해줍니다.

| 구분       | 역할                                              |
| ---------- | ------------------------------------------------- |
| PostgreSQL | 실제 데이터를 저장하고 SQL을 실행합니다.          |
| ORM        | 애플리케이션의 객체와 관계형 데이터를 연결합니다. |

PostgreSQL은 데이터를 보관하고 관리하는 시스템이고, ORM은 애플리케이션에서 그 데이터를 다루는 것을 도와주는 도구입니다.

## 3. Node.js에서는 어떤 ORM을 사용할까?

Node.js와 TypeScript 환경에서는 TypeORM 외에도 여러 ORM을 사용할 수 있습니다.

| 도구           | 기본적인 특징                                                                                 |
| -------------- | --------------------------------------------------------------------------------------------- |
| **TypeORM**    | 클래스와 데코레이터로 엔티티를 정의하고, 리포지토리 등을 통해 데이터를 다룹니다.              |
| **Prisma ORM** | 스키마에 데이터 모델을 정의하고 타입 정보를 활용해 데이터를 조회·변경합니다.                  |
| **MikroORM**   | 엔티티를 중심으로 데이터를 다루며, 객체의 변경 사항을 추적해 DB에 반영하는 구조를 제공합니다. |

이 도구들은 객체와 데이터베이스 사이의 작업을 돕는다는 공통점이 있지만, 데이터 구조를 정의하고 조회·저장을 표현하는 방식에는 차이가 있습니다.

현재 배우는 **TypeORM은 ORM을 구현한 여러 도구 중 하나**입니다. NestJS 자체의 기능은 아니며, NestJS에서는 `@nestjs/typeorm` 패키지를 통해 모듈과 의존성 주입 구조에 통합해서 사용할 수 있습니다.

## 4. 엔티티란?

엔티티는 여러 맥락에서 사용하는 용어지만, **TypeORM에서는 데이터베이스 테이블에 매핑되는 클래스**를 의미합니다.

게시글 엔티티라면 게시글을 구성하는 ID, 제목, 내용 등의 속성을 정의합니다. 그리고 각 속성이 테이블의 어떤 컬럼에 대응하는지 ORM에 알려줍니다.

다음은 구조를 이해하기 위한 간단한 TypeORM 엔티티 예제입니다.

```ts
import { Column, Entity, PrimaryGeneratedColumn } from 'typeorm';

@Entity('posts')
export class Post {
  @PrimaryGeneratedColumn()
  id!: number;

  @Column()
  title!: string;

  @Column()
  content!: string;
}
```

`@Entity('posts')`는 이 클래스를 `posts` 테이블에 연결합니다. `@Column()`은 속성을 컬럼에 연결하고, `@PrimaryGeneratedColumn()`은 자동으로 값을 생성하는 기본 키를 정의합니다. 기본 키는 각 행을 구분하는 식별자입니다.

속성의 `!`는 TypeScript에 초기화를 나중에 처리한다고 알리는 표기입니다. 값을 검증하거나 실제로 대입하는 기능은 없습니다.

| 애플리케이션                         | 데이터베이스      |
| ------------------------------------ | ----------------- |
| `Post` 엔티티 클래스                 | `posts` 테이블    |
| `title` 속성                         | `title` 컬럼      |
| 게시글 데이터를 담은 엔티티 인스턴스 | 테이블의 행 한 건 |

엔티티는 단순히 데이터 모양만 표현하는 것이 아니라, **객체를 어떤 테이블과 컬럼에 연결할지 정의하는 역할**을 합니다.

## 5. 리포지토리란?

리포지토리는 데이터를 조회하고 저장하는 작업을 담당하는 창구로 이해할 수 있습니다. 게시글 리포지토리라면 게시글 목록 조회, 특정 게시글 조회, 저장, 수정, 삭제 같은 작업을 제공합니다.

TypeORM의 리포지토리는 특정 엔티티를 대상으로 동작합니다. 게시글 엔티티의 리포지토리는 게시글 데이터를 다루고, 사용자 엔티티의 리포지토리는 사용자 데이터를 다룹니다.

아래는 **DB 연결이 초기화되고 `Post` 엔티티가 등록되어 있다고 가정한 예제**입니다.

```ts
const postRepository = dataSource.getRepository(Post);
const posts = await postRepository.find();
```

첫 줄은 `Post` 엔티티의 리포지토리를 가져오고, 두 번째 줄은 해당 리포지토리로 게시글 목록을 조회합니다. `await`는 비동기로 실행되는 DB 작업이 끝나기를 기다리는 데 사용합니다.

앞서 본 SQL과 이 예제는 모두 게시글 조회를 표현하지만, ORM이 실제 생성하는 SQL과 조회 컬럼은 메서드와 설정에 따라 달라질 수 있습니다.

**엔티티는 ‘어떤 데이터를 어떤 테이블에 연결할지’를 정의하고, 리포지토리는 ‘그 데이터를 조회하고 저장하는 작업’을 제공합니다.** 리포지토리가 데이터를 보관하는 장소 자체는 아니며, 실제 데이터는 PostgreSQL에 저장됩니다.

## 6. 함께 연결해서 이해하기

게시글을 저장하거나 조회하는 상황으로 생각하면 각 역할을 연결하기 쉽습니다.

![TypeORM 안에서 엔티티 매핑을 참고해 리포지토리가 PostgreSQL에 데이터 작업을 요청하는 관계](/images/nestjs-typeorm-relationship.svg)

게시글의 구조와 테이블 매핑은 **엔티티**로 정의합니다. 애플리케이션은 **리포지토리**를 통해 조회나 저장을 요청합니다. **TypeORM**은 엔티티의 매핑 정보를 바탕으로 SQL을 구성하고 드라이버를 통해 DB와 통신하며, **PostgreSQL**은 SQL을 실행해 데이터를 조회하거나 저장합니다.

엔티티는 요청이 순서대로 통과하는 단계라기보다, ORM이 DB 작업을 처리할 때 참고하는 연결 규칙입니다.

## 7. 기억할 점

ORM을 사용하면 반복적인 데이터 접근 코드를 줄일 수 있습니다. 다만 테이블 구조나 SQL 실행이 사라지는 것은 아니므로, 기본적인 SQL과 관계형 데이터베이스 개념도 함께 익혀야 합니다.

또한 엔티티를 정의하거나 객체를 생성했다고 해서 데이터가 자동으로 저장되지는 않습니다. 실제 저장 작업은 별도로 수행해야 합니다. TypeORM에서 엔티티 클래스를 선언하는 것과 DB 테이블을 실제 생성·변경하는 작업도 구분해야 합니다.
