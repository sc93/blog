오늘은 NestJS에서 요청 데이터를 처리하는 Pipe를 공부했습니다. 요청값의 타입을 변환하는 방법과, 전달받은 데이터가 정해진 조건을 만족하는지 검증하는 방법을 배웠습니다.

Pipe가 어떤 역할을 하는지, `ParseIntPipe`와 `ValidationPipe`는 어떻게 다른지 복습하며 정리해 보겠습니다.

## 1. Pipe란?

Pipe는 Controller의 라우트 핸들러가 실행되기 전에 요청 인자를 처리하는 기능입니다.

클라이언트가 보낸 데이터는 서버에서 기대한 형태와 다를 수 있습니다. 숫자가 필요한 곳에 문자열이 들어오거나, 필수 항목이 비어 있을 수도 있습니다. Pipe는 이런 값을 변환하거나 검증하는 데 사용합니다.

| 역할 | 의미                                      | 예시                                    |
| ---- | ----------------------------------------- | --------------------------------------- |
| 변환 | 값을 필요한 타입이나 형태로 바꿉니다.     | 문자열 `"10"`을 숫자 `10`으로 변환      |
| 검증 | 값이 정해진 조건을 만족하는지 확인합니다. | 제목이 문자열이고 비어 있지 않은지 확인 |

Pipe가 값을 정상적으로 처리하면 결과가 핸들러에 전달됩니다. 검증에 실패해 예외가 발생하면 핸들러는 실행되지 않습니다.

```text
요청 인자 → Pipe → Controller 핸들러
                ↘ 검증 실패 시 오류 응답
```

## 2. TypeScript 타입만 지정하면 안 될까?

다음처럼 `id`에 `number` 타입을 지정했다고 생각해 보겠습니다.

```ts
@Param('id') id: number
```

이 선언만으로 HTTP 요청의 문자열이 실제 숫자로 바뀌지는 않습니다.

TypeScript의 타입 검사는 개발·컴파일 단계에서 이루어집니다. 반면 클라이언트의 요청은 애플리케이션이 실행되는 도중에 들어옵니다.

따라서 **타입을 선언하는 것과 실제 요청값을 변환·검증하는 것은 별개의 작업**입니다.

## 3. ParseIntPipe란?

`ParseIntPipe`는 값을 정수로 변환하는 NestJS 내장 Pipe입니다. 정수로 변환할 수 없는 값은 거부합니다.

예를 들어 URL의 게시글 ID를 숫자로 사용하고 싶다면 다음처럼 적용할 수 있습니다.

```ts
@Get(':id')
findOne(@Param('id', ParseIntPipe) id: number) {
  return { id };
}
```

| 요청              | 처리 결과                       |
| ----------------- | ------------------------------- |
| `GET /boards/10`  | 핸들러에 숫자 `10` 전달         |
| `GET /boards/abc` | 기본적으로 400 Bad Request 응답 |

`ParseIntPipe`는 단순히 타입만 바꾸는 것이 아니라, 정수로 처리할 수 있는 값인지도 확인합니다.

## 4. ValidationPipe란?

`ValidationPipe`는 DTO에 선언한 검증 규칙을 이용해 요청 데이터를 검사하는 Pipe입니다.

예를 들어 게시글 제목은 문자열이어야 하고, 빈 값이면 안 된다는 조건을 정의할 수 있습니다.

```ts
import { IsNotEmpty, IsString } from 'class-validator';

export class CreateBoardDto {
  @IsString()
  @IsNotEmpty()
  title!: string;
}
```

| 데코레이터      | 검증 내용                                    |
| --------------- | -------------------------------------------- |
| `@IsString()`   | 문자열인지 확인                              |
| `@IsNotEmpty()` | 빈 문자열, `null`, `undefined`가 아닌지 확인 |

`title!`의 `!`는 TypeScript에 초기화를 나중에 처리한다고 알리는 표기입니다. 입력값을 검증하는 기능은 없습니다.

또한 DTO에 검증 규칙을 작성하는 것만으로 검사가 실행되지는 않습니다. **실제 요청에 `ValidationPipe`를 적용해야 합니다.**

```ts
@Post()
@UsePipes(new ValidationPipe())
create(@Body() dto: CreateBoardDto) {
  return dto;
}
```

이 예제에서는 제목으로 빈 문자열이 들어오면 검증에 실패하고, 기본적으로 400 Bad Request 응답을 반환합니다.

## 5. class-validator와 class-transformer는 무엇일까?

`ValidationPipe`를 배우면서 두 라이브러리도 함께 등장했습니다.

| 도구                | 역할                                                                     |
| ------------------- | ------------------------------------------------------------------------ |
| `class-validator`   | 데코레이터로 선언한 규칙에 따라 값을 검증합니다.                         |
| `class-transformer` | 일반 객체를 클래스 인스턴스로 바꾸는 등의 변환을 지원합니다.             |
| `ValidationPipe`    | 이 도구들을 활용해 NestJS의 요청 처리 과정에서 검증과 변환을 수행합니다. |

즉, `@IsString()` 같은 규칙은 `class-validator`가 제공하고, NestJS의 `ValidationPipe`가 요청 처리 과정에서 그 규칙을 적용합니다.

## 6. ValidationPipe의 주요 옵션

`ValidationPipe`에는 요청 데이터를 어떻게 처리할지 결정하는 옵션이 있습니다.

```ts
new ValidationPipe({
  whitelist: true,
  forbidNonWhitelisted: true,
  transform: true,
});
```

| 옵션                   | 의미                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------- |
| `whitelist`            | 검증 데코레이터가 없는 속성을 제거합니다.                                          |
| `forbidNonWhitelisted` | `whitelist`와 함께 사용하면, 허용하지 않은 속성을 제거하는 대신 오류를 반환합니다. |
| `transform`            | 요청값을 DTO 클래스 인스턴스 등으로 변환해 핸들러에 전달합니다.                    |

예를 들어 DTO에 검증 규칙이 있는 속성이 `title`뿐인데 요청에 `admin` 속성까지 들어왔다면, `whitelist` 설정에 따라 해당 속성을 제거하거나 요청을 거부할 수 있습니다.

여기서 기준은 **DTO에 속성이 선언되어 있는지뿐 아니라, 검증 데코레이터가 적용되어 있는지**입니다.

## 7. 기억할 점

변환과 검증은 목적이 다릅니다. 값을 숫자로 바꿨다고 해서 양수인지까지 보장되는 것은 아니며, 문자열이라고 해서 의미 있는 내용이 들어 있다는 보장도 없습니다.

예를 들어 `@IsNotEmpty()`는 공백만 있는 문자열까지 거부하지는 않습니다. 실제로 허용할 값의 조건에 맞춰 검증 규칙을 정해야 합니다.

또한 `transform: true`를 설정했다고 모든 DTO 속성이 원하는 타입으로 자동 변환되는 것은 아닙니다. 타입 변환과 검증 규칙을 구분해서 이해하는 것이 중요합니다.
