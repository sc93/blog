## 1. 요청은 어디서 처리될까?

게시글 API를 예로 들면 요청은 Controller로 들어오고, Controller는 Service를 호출합니다. Module은 이 구성 요소들을 NestJS에 등록합니다.

```txt
GET /boards
    ↓
BoardsController
    ↓
BoardsService
    ↓
게시글 데이터 반환
```

Module은 매 요청을 중간에서 처리하는 단계가 아니라, 애플리케이션이 시작될 때 Controller와 Provider를 구성하는 역할을 합니다.

## 2. Module: 기능 단위로 구성하기

```ts
@Module({
  imports: [],
  controllers: [BoardsController],
  providers: [BoardsService],
})
export class BoardsModule {}
```

- <code>imports</code>: 다른 모듈이 공개한 Provider 등을 사용할 때 해당 모듈을 가져옵니다.
- <code>controllers</code>: HTTP 요청을 처리할 Controller를 등록합니다.
- <code>providers</code>: NestJS가 관리하고 주입할 Provider를 등록합니다.
- <code>exports</code>: 다른 모듈에서 사용할 Provider 등을 공개합니다.

게시글 기능을 <code>BoardsModule</code>로 분리하면 관련 코드를 한 단위로 관리할 수 있습니다. 실제 프로젝트에서는 <code>AppModule</code>의 <code>imports</code>에 <code>BoardsModule</code>을 등록합니다.

## 3. Controller: 요청을 받고 Service 호출하기

```ts
@Controller('boards')
export class BoardsController {
  constructor(private readonly boardsService: BoardsService) {}

  @Get()
  getAllBoards() {
    return this.boardsService.getAllBoards();
  }

  @Get(':id')
  getBoardById(@Param('id') id: string) {
    return this.boardsService.getBoardById(id);
  }
}
```

- <code>@Controller('boards')</code>: 공통 경로를 설정합니다.
- <code>@Get()</code>: <code>GET /boards</code> 요청을 처리합니다.
- <code>@Get(':id')</code>: <code>GET /boards/1</code>과 같은 요청을 처리합니다.
- <code>@Param('id')</code>: URL 경로의 <code>id</code> 값을 가져옵니다.

Controller는 요청과 응답을 연결하는 역할에 집중하고, 실제 게시글 조회나 저장 로직은 Service로 분리합니다.

## 4. Provider와 Service: 실제 로직 작성하기

```ts
@Injectable()
export class BoardsService {
  private readonly boards = [{ id: 1, title: '첫 글' }];

  getAllBoards() {
    return this.boards;
  }

  getBoardById(id: string) {
    return this.boards.find((board) => board.id === Number(id));
  }
}
```

Service는 비즈니스 로직을 담당하는 일반적인 클래스이며, NestJS에서는 대표적인 Provider로 사용합니다.

<code>@Injectable()</code>은 DI 관련 메타데이터를 제공하지만, 이 데코레이터만으로 모든 모듈에서 자동 사용되는 것은 아닙니다. 일반적으로 모듈의 <code>providers</code>에 등록하거나 다른 모듈에서 공개한 Provider를 가져와야 합니다.

## 5. DI: 직접 생성하지 않고 주입받기

```ts
// 직접 생성
private readonly boardsService = new BoardsService();

// NestJS 생성자 주입
constructor(private readonly boardsService: BoardsService) {}
```

DI(Dependency Injection)는 필요한 객체를 클래스 내부에서 직접 생성하는 대신 외부에서 전달받는 방식입니다. NestJS는 등록된 Provider를 생성하고 필요한 곳에 주입합니다.

DI의 핵심은 <b>객체 생성과 사용의 책임을 분리</b>하는 것입니다. 덕분에 의존성을 교체하거나 테스트하기가 수월해집니다.

## 6. 복습 포인트

- Module은 Controller와 Provider를 묶어 애플리케이션의 구성을 정의합니다.
- Controller는 HTTP 요청을 처리하고 Service를 호출합니다.
- Service는 비즈니스 로직을 담당하며 Provider로 등록할 수 있습니다.
- <code>@Injectable()</code>과 <code>providers</code> 등록은 같은 의미가 아닙니다.
- DI는 의존성 전달 방식이고, 싱글톤은 인스턴스 공유 방식입니다.
