> NestJS로 게시글 API를 구현하면서 요청 데이터와 애플리케이션 내부 데이터의 구조를 어떻게 구분할지 정리했습니다. 이번 글에서는 Model과 DTO의 기본적인 역할만 살펴보고, 실제 입력값 검증은 다음 편에서 다룹니다.

## 1. Model과 DTO는 왜 구분할까?

게시글 생성 요청에는 보통 <code>title</code>과 <code>description</code>이 필요합니다. 하지만 서버에서 관리하는 게시글 데이터에는 <code>id</code>도 포함될 수 있습니다.

즉, <b>클라이언트가 보내는 데이터의 형태</b>와 <b>서버가 관리하는 데이터의 형태</b>는 같지 않을 수 있습니다.

- <b>Model</b>: 애플리케이션에서 다루는 데이터의 구조를 표현합니다.
- <b>DTO(Data Transfer Object)</b>: 요청이나 응답처럼 계층 사이에 전달되는 데이터의 형태를 정의합니다.

NestJS가 Model이나 DTO의 특정 파일 구조를 강제하는 것은 아닙니다. 프로젝트의 필요에 따라 정의할 수 있습니다.

## 2. 게시글 Model 정의하기

우선 게시글의 데이터 구조를 TypeScript 인터페이스로 정의합니다.

```ts
// board.model.ts
export interface Board {
  id: number;
  title: string;
  description: string;
}
```

<code>Board</code>는 게시글이 어떤 필드를 갖는지 표현합니다. 이 인터페이스는 TypeScript의 타입 검사에 사용되며, 실행 시점에는 제거됩니다.

데이터베이스를 연결할 때는 사용하는 ORM이나 라이브러리에 따라 별도의 엔티티 또는 스키마 정의가 필요할 수 있습니다. 여기서는 아직 다루지 않겠습니다.

## 3. 생성 요청에 사용할 DTO 정의하기

게시글을 생성할 때 클라이언트가 <code>id</code>까지 전달할 필요는 없습니다. 따라서 생성 요청의 데이터 형태를 별도로 정의합니다.

```ts
// dto/create-board.dto.ts
export class CreateBoardDto {
  title: string;
  description: string;
}
```

<code>CreateBoardDto</code>는 게시글 생성 요청에서 기대하는 필드를 표현합니다. DTO는 일반적으로 클래스로 작성하며, 이후 검증 데코레이터를 적용할 때도 활용할 수 있습니다.

여기서 주의할 점은 <b>DTO 클래스를 정의했다고 해서 요청값이 자동으로 검증되는 것은 아니라는 점</b>입니다. 실제 런타임 검증에는 별도의 설정이 필요합니다.

## 4. Controller에서 요청 데이터 받기

```ts
// boards.controller.ts
@Post()
createBoard(@Body() createBoardDto: CreateBoardDto): Board {
  return this.boardsService.createBoard(createBoardDto);
}
```

<code>@Body()</code>는 HTTP 요청 본문을 가져옵니다. 요청 데이터가 DTO 형태를 따른다고 선언한 뒤 Service로 전달합니다.

예를 들어 클라이언트가 다음 JSON을 전송할 수 있습니다.

```json
{
  "title": "첫 번째 게시글",
  "description": "NestJS 학습 중입니다."
}
```

현재 코드에서 <code>CreateBoardDto</code> 타입을 지정하는 것은 개발 단계의 타입 검사에 도움이 되지만, 실제 요청 본문에 문자열이 들어왔는지 또는 필수 필드가 있는지를 보장하지는 않습니다.

## 5. Service에서 게시글 생성하기

```ts
// boards.service.ts
@Injectable()
export class BoardsService {
  private boards: Board[] = [];

  createBoard(createBoardDto: CreateBoardDto): Board {
    const board: Board = {
      id: this.boards.length + 1,
      ...createBoardDto,
    };

    this.boards.push(board);
    return board;
  }
}
```

Controller는 요청 데이터를 받아 전달하고, Service는 전달받은 데이터를 바탕으로 게시글을 생성합니다.

이 예제는 데이터 흐름을 설명하기 위한 간단한 코드입니다. 실제 서비스에서는 유효성 검증과 영속 저장 등을 추가해야 합니다.

## 6. 정리

- Model은 애플리케이션에서 다루는 데이터의 구조를 표현합니다.
- DTO는 요청 또는 응답에서 전달할 데이터의 형태를 정의합니다.
- <code>@Body()</code>로 요청 본문을 받아 DTO 타입으로 표현할 수 있습니다.
- TypeScript의 타입 선언만으로 외부에서 들어오는 데이터를 런타임에 검증할 수는 없습니다.
- Controller는 요청을 전달하고, Service는 게시글 생성 로직을 수행하도록 분리할 수 있습니다.
