# 변경 검증 지침

검증 계획을 세우거나 완료를 보고하기 전에 읽는다. 실제 변경의 영향 범위에 맞는 검증을 실행한다.

## 변경 종류별 검증

| 변경 종류                     | 검증 기준                                                                                                                                                 |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 애플리케이션 동작·설정·의존성 | 관련 테스트와 `pnpm test`, `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm build`를 실행한다. 영향받는 화면·응답도 확인한다.                    |
| 글 작성·수정·공개             | 포맷과 콘텐츠 검증, 빌드로 메타데이터·MDX 렌더링·공개 여부를 확인한다. 초안·SEO 노출에 영향을 주면 상세·목록·RSS·Sitemap도 확인한다.                      |
| 문서만 변경                   | 변경 문서의 Prettier 검사, `git diff --check`, 문서 내용과 링크의 일관성을 확인한다. 불필요한 애플리케이션 테스트를 만들거나 전체 빌드를 실행하지 않는다. |

## 공통 원칙

- 동작 변경에는 경계 조건과 초안 노출 등 의미 있는 검증을 추가한다. 구현을 그대로 복제하는 테스트는 피한다.
- Prettier의 기존 import 및 Tailwind 정렬 설정을 사용한다. 커밋 훅은 변경 파일만 검사한다.
- 커밋 훅 통과를 전체 테스트나 빌드의 성공으로 대신하지 않는다.
- 실행한 명령과 실제 결과를 확인하고, 미검증 항목과 실패·환경 제한을 명시한다. 실행하지 못한 검증을 성공으로 보고하지 않는다.
- 같은 결과를 확인하기 위한 검증은 변경이나 새 우려가 생겼을 때 다시 실행한다.
